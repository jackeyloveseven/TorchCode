梯度累积

显存不够时的大 batch 模拟：多步累积梯度，一次 optimizer.step。

学习目标

  • 理解梯度累积模拟大 batch 的原理
  • 掌握 loss / n_accum 的正确 loss 缩放方式
  • 能写出标准的梯度累积训练循环

核心概念

为什么要梯度累积？

# 目标：用 batch_size=256 训练，但显存只能放 batch_size=32
# 方案：累积 8 个 micro batch 的梯度 → 等效于 256

# 数学等价性：
# E[grad(256)] = E[grad(32)] * 8 / 8 = E[grad(32)]
# 但梯度累积是连续批次的平均，有轻微差异（BN 统计等）

Loss 缩放的关键

# 错误写法：
loss.backward()  # 梯度 = sum(grad_i)，比 mean 大 n 倍
optimizer.step() # 步子过大！

# 正确写法：
loss = criterion(pred, label) / n_accum  # 除以累积步数
loss.backward()  # 梯度 = sum(grad_i) / n = mean
optimizer.step() # 正确步长

PyTorch 实现

n_accum = 4   # 累积 4 步 = 模拟 4x batch size

optimizer.zero_grad()
for step, (x, y) in enumerate(dataloader):
    # 前向 + 反向（不 step）
    pred = model(x)
    loss = criterion(pred, y) / n_accum   # ← 关键！
    loss.backward()   # 梯度累积在 .grad 中

    if (step + 1) % n_accum == 0:
        # 累积了 n_accum 步后，执行优化
        optimizer.step()
        optimizer.zero_grad()   # 清空梯度，准备下一轮
与 DDP 的关系：多卡 DDP 也是梯度累积的一种——每卡 forward 后只在 step 时 all-reduce 同步梯度。 梯度累积 + DDP 一起用时，还要注意 model.no_sync() 防止中间步骤同步（浪费通信）。

测验

Q1 · Loss 缩放

累积 4 步时，每步的 loss 应该如何缩放？

  • A 乘以 4（放大梯度）
  • B 不缩放（直接用原始 loss）
  • C 除以 4（缩放成等效的平均梯度）
  • D 乘以 0.1（防止梯度爆炸）

Q2 · zero_grad 时机

梯度累积时，optimizer.zero_grad() 应该在什么时候调用？

  • A 每步 backward 之前
  • B 每 n_accum 步的 optimizer.step() 之后
  • C 每步 backward 之后
  • D 训练开始前一次，之后不需要

Q3 · 为什么能累积

PyTorch 为什么能"自动"累积梯度？

  • A backward 会累加梯度到 .grad，不自动清零
  • B PyTorch 内部有缓冲区自动管理
  • C 每次 backward 会保存历史梯度
  • D 需要显式调用 grad_accum() 函数

参考解法

n_accum = 4
optimizer.zero_grad()
for step, (x, y) in enumerate(dataloader):
    pred = model(x)
    loss = criterion(pred, y) / n_accum
    loss.backward()
    if (step + 1) % n_accum == 0:
        optimizer.step()
        optimizer.zero_grad()

面试要点

  • 公式：loss / n_accum，累积 n 步后 step
  • 原理：backward 累加到 .grad，step 后用累积梯度更新
  • 等价性：梯度累积 ≈ 更大 batch（BatchNorm 统计除外）
  • DDP + 累积：中间步骤用 model.no_sync() 避免多余的 all-reduce
