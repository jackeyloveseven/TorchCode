交叉注意力

Encoder-Decoder 桥梁：Q 来自解码器，K/V 来自编码器。

学习目标

  • 理解交叉注意力与自注意力的本质区别
  • 掌握 Q/K/V 来自不同序列的实现
  • 理解为什么交叉注意力不需要因果掩码

核心概念

自注意力 vs 交叉注意力

自注意力交叉注意力
Q 来源当前序列 x解码器隐状态 query
K/V 来源当前序列 x编码器输出 context
因果掩码解码时需要不需要（context 全可见）
用途序列内交互跨序列信息查询

典型应用

  • 机器翻译：解码器关注编码器的源语言表示
  • 图像生成（Stable Diffusion）：图像特征关注文本 embedding
  • 多模态模型：文本 token 关注视觉特征

PyTorch 实现

def cross_attention(query, context, W_q, W_k, W_v, W_o):
    # query:   (B, S_q, D) — 解码器隐状态
    # context: (B, S_c, D) — 编码器输出
    B, S_q, D = query.shape
    d_k = D

    Q = W_q(query)      # (B, S_q, D)，来自解码器
    K = W_k(context)    # (B, S_c, D)，来自编码器
    V = W_v(context)    # (B, S_c, D)，来自编码器

    scores  = torch.bmm(Q, K.transpose(1, 2)) / math.sqrt(d_k)
    # 无因果掩码：解码器的每个位置可以看整个 context
    weights = torch.softmax(scores, dim=-1)   # (B, S_q, S_c)
    out = torch.bmm(weights, V)               # (B, S_q, D)
    return W_o(out)
scores 的形状： (B, S_q, S_c)，不是 (B, S_q, S_q)。 S_q 和 S_c 可以不同（解码器长度 ≠ 编码器长度）。

测验

Q1 · 来源

在 Encoder-Decoder 的交叉注意力中，K 和 V 来自哪里？

  • A 解码器的隐状态
  • B 编码器的输出（context）
  • C 位置编码
  • D 可学习的固定参数

Q2 · scores 形状

S_q=10, S_c=20，交叉注意力 scores 的形状是？

  • A (B, 10, 10)
  • B (B, 20, 20)
  • C (B, 10, 20)
  • D (B, 20, 10)

Q3 · 是否需要因果掩码

交叉注意力为什么不需要因果掩码？

  • A context 是完整序列，没有"未来位置"的信息泄露问题
  • B 计算太慢，掩码省略
  • C 因果掩码只用于 FFN，不用于注意力
  • D 交叉注意力用于推理，不用于训练

参考解法

def cross_attention(query, context, W_q, W_k, W_v, W_o):
    d_k = query.size(-1)
    Q = W_q(query)
    K = W_k(context)
    V = W_v(context)
    scores  = torch.bmm(Q, K.transpose(1, 2)) / math.sqrt(d_k)
    weights = torch.softmax(scores, dim=-1)
    out = torch.bmm(weights, V)
    return W_o(out)

面试要点

  • 区别：Q 来自 decoder，K/V 来自 encoder
  • 无因果掩码：context 全可见
  • scores 形状：(B, S_q, S_c)，S_q ≠ S_c 也可以
  • 应用：T5、BART、Stable Diffusion 的 UNet
